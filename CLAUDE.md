- **Commit policy:** (stage-only | auto-commit | draft-PR | never-commit) — set during `/setup`. **Kit default: stage-only — agents stage, the human commits.** Even a commit message supplied earlier is not commit authorization. **When a commit is warranted, prompt the owner with a proposed message** rather than composing one unprompted. Messages: short prose, a subject plus at most a line or two; reference the issue when one exists.
- **Default branch:** (auto-detected) · **Branch protection:** (block direct pushes | warn-and-confirm | none) · **Branching:** short-lived branches only for experimental work, named `<issue-id>-<kebab-description>`.
- **Issue tracker:** (where status lives; how an agent reads the real issue id — **never infer an id from a numbering pattern**, a wrong `Closes #n` auto-closes an unrelated issue).
- **Handoffs (two cases only):** a handoff is written unprompted **(1)** when the same task continues in a new session because this one has filled up (rotation at ~40 % of the window), or **(2)** when the task is done and a clear next ticket exists. A finished topic with no successor writes none: archive the consumed handoff to `docs/handoff/archive/`, put loose notes in auto-memory, stop. Invoke `/handoff`; the shape is `.claude/skills/handoff/template.md`, never the previous handoff; say in the recap that you wrote it. **A ratification the owner makes mid-ticket is written to the handoff draft or to auto-memory at that moment, never held for session end.** **Two modes** (`WORKFLOW.md` §4.1): *manual*, one ticket per session as above; *dispatch*, one session runs `/next-ticket` and gives each ticket to a fresh `ticket-agent`. The owner picks (close of `/plan-interview`, the handoff's `Mode:` line, or by asking) and can switch at any time.
